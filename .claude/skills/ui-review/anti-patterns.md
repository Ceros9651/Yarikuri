# AIっぽいUIの検出基準

レビューで探すのは次の4カテゴリ。どれも「それ自体が悪」ではなく、**情報の重みや操作の流れと無関係に、全体へ一律にかかっている**ときに問題になる。指摘するときは、その画面でなぜ不要なのか（または何に置き換えるべきか）まで言えるものだけを出す。

このリポジトリのスタイルは `src/index.css` の1ファイル（素の CSS、`:root` の CSS 変数＋クラス名）。UI ライブラリ・アイコンライブラリ・Tailwind は使っていない。以下の兆候も CSS のプロパティとクラス名で書いている。

## 1. 角丸カードの多用

### 兆候

- 画面の大半の情報が `.card`（`border-radius: var(--radius)` = 12px、`background: var(--surface)`）に入っている。`.card` の中にさらに枠や背景付きの塊がある（カードの入れ子）。
- 月の集計、口座残高、カテゴリ内訳、フォーム、設定の各セクションなど、性質の違う情報がすべて同じ `.card` で包まれている。
- 境界線（`border`）・背景色（`--surface` と `--bg` の差）・影（`box-shadow`）の3つを同時に使って区切っている。
- `button` / `input` / `.notice` / `.segmented` / `.card` の角丸が 8〜12px で揃っていて、部品の大きさと関係なく同じ丸さに見える。
- `.summary-grid` のように、数値1つずつを小さなカードに入れて並べている。

### 計測の目安

- 表示要素のうち `border-radius` ≥ 8px の要素が多数を占める。
- 背景か枠を持つ塊の入れ子が2段以上。

### 置き換えの方向

- 同種の情報の並びは罫線・余白で区切る（`.list > li` の下線のように）。
- 箱で囲むのは「独立して操作するもの」「他と区別すべき塊」に限る。
- 角丸は部品の大きさに応じて小さく（例: 入力欄・ボタン 4〜6px、塊 8px 以下、または0）。変えるなら `:root` の `--radius` と個別の `border-radius` の両方を見る。

## 2. 飾りアイコン・絵文字

### 兆候

- 見出し、ラベル、統計値、メニュー項目の横に絵文字（🏠📋✏️⚙️✨📊💰 など）やインライン svg がある。
- アイコンが文字と同じ意味を繰り返しているだけ（「設定」の横の ⚙️ など）で、文字だけでも足りる場所にある。
- アイコンや絵文字を色付きの丸や角丸四角の背景に入れている。
- 空状態（`.empty`）や完了メッセージに絵文字を添えている。
- 絵文字は OS ごとに見た目が変わり、色も制御できないため、アプリの配色と馴染まない。

### 置き換えの方向

- アイコンは「文字なしで機能するもの」（閉じる、並べ替えのつまみ、月の前後）と、狭い場所での操作に限る。
- タブバーのように「アイコン＋文字」が定着している場所は、消すのではなく、絵文字をアプリの色に合う線画（インライン svg、`currentColor`）に置き換える方向を検討する。
- ラベルがある場所では、アイコンを外して文字の太さ・大きさ・位置で区別する。
- 空状態はイラストやアイコンではなく、次にやることを短い文とボタンで示す。

## 3. 紫青グラデ・影の多用

### 兆候

- 背景、ボタン、テキストに紫〜青〜ピンクのグラデーション（`background: linear-gradient(...)`, `background-clip: text`）。
- 多くの塊やボタンに `box-shadow`。`:hover` / `:active` で影が強くなる・浮き上がる（`transform: translateY`）。
- ガラス風（`backdrop-filter: blur()` ＋ 半透明の背景）が重要でない場所に使われている。
- アクセント色が `--primary` 以外にも増えていて、強調があちこちに散っている。

### 置き換えの方向

- 色は無彩色の段階（`--bg` / `--surface` / `--surface-2` / `--border` / `--text-muted`）を主にし、アクセント色は `--primary` の1つ、使う場所を絞る（主ボタン、選択状態、リンク）。収入・出費の色（`--income` / `--expense`）は金額の意味を示すためのものなので、飾りに流用しない。
- 階層は影ではなく、背景の明度差・罫線・重なり順で示す。影は実際に上に浮くもの（メニュー、ドラッグ中の行 `.sortable-row.dragging`）だけ。
- グラデーションはブランド上の理由がない限り使わない。
- ダークモード（`@media (prefers-color-scheme: dark)` の `:root`）でも同じ方針になっているかを見る。

## 4. 均一な余白と中央寄せ

### 兆候

- どのセクションも同じ `padding` / `margin-bottom: 12px` / `gap: 8px`。関係の近いもの同士と遠いもの同士の間隔が同じ。
- 数値や見出しが `text-align: center` で中央に寄っていて、一覧として縦に読みにくい（例: `.summary-grid .card`）。
- 同じサイズの塊を `grid-template-columns: repeat(3, 1fr)` で並べたレイアウトが繰り返される。
- 見出し（`h1` / `h2` / `h3`）の大きさの段階が少なく、どこから読むべきかが分からない。金額などいちばん見たい数字が他と同じ大きさ。

### 計測の目安

- padding / margin / gap の値の種類が1〜2種類しかない。
- 主要コンテンツの text-align が center。

### 置き換えの方向

- 関係の近いものは詰め、区切りたいところは大きく空ける（余白に段階を作る）。
- 文章や表は左揃え、金額は右揃え（桁が揃うように `font-variant-numeric: tabular-nums`）。中央揃えは短い単独メッセージ程度に限る。
- 重要な情報（今月の差額、残高）を大きく・上に置き、補助情報を小さく・後ろに置く。均等なグリッドより、主と従のある配置にする。
- 毎日使う画面なので、情報密度は高めでよい。スクロールせずに見たいものが見えるかを優先する。

## 方針違反
