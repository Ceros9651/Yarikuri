# data-backup Specification

## Purpose

データは端末内にしか保存されないため、全データをファイルに書き出して保管し、機種変更やデータ消失時に別の端末や同じ端末へ復元できるようにする。

## Requirements

### Requirement: JSON エクスポート
ユーザーは設定画面から、口座・カテゴリ・取引の全データを1つの JSON ファイルとして SHALL ダウンロード（またはスマホの共有メニューで保存）できる。ファイルにはデータ形式のバージョンとエクスポート日時を含めなければならない（MUST）。ファイル名にはエクスポート日付を含める。

#### Scenario: バックアップを書き出す
- **WHEN** ユーザーが設定画面で「エクスポート」を押す
- **THEN** `yarikuri-backup-2026-10-09.json` のような名前で、全データを含む JSON ファイルが保存できる

### Requirement: JSON インポート
ユーザーはエクスポートした JSON ファイルを選択して、端末内の全データをファイルの内容で SHALL 置き換えられる。置き換えの前に、既存データが上書きされることを確認しなければならない（MUST）。

#### Scenario: バックアップから復元する
- **WHEN** ユーザーがエクスポートしたファイルを選び、上書き確認で「置き換える」を選ぶ
- **THEN** 口座・カテゴリ・取引がファイルの内容と同じになり、ホーム画面の集計もそれに基づいて表示される

#### Scenario: 上書き確認でキャンセルする
- **WHEN** ユーザーがファイルを選んだあと、上書き確認でキャンセルを選ぶ
- **THEN** 端末内のデータは変更されない

### Requirement: 不正なファイルの拒否
インポートするファイルが JSON として読めない、必要な項目がない、対応していないバージョンである、または取引が存在しない口座・カテゴリを参照している場合、システムはインポートを中止し、既存データを一切変更してはならない（MUST NOT）。中止した理由を SHALL 表示する。

#### Scenario: 壊れたファイルを選ぶ
- **WHEN** ユーザーが JSON として不正なファイルを選ぶ
- **THEN** エラーメッセージが表示され、端末内のデータは変更されない

### Requirement: エクスポートとインポートの往復
エクスポートしたファイルをインポートした結果は、エクスポート時点のデータと SHALL 一致しなければならない。

#### Scenario: 別の端末へ移行する
- **WHEN** 端末Aでエクスポートしたファイルを、データのない端末Bでインポートする
- **THEN** 端末Bのホーム画面・取引一覧・口座・カテゴリは端末Aのエクスポート時点と同じ内容で表示される
