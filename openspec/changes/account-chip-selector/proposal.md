# Proposal

## Why

取引入力画面のカテゴリは1タップで選べるチップ型になったが、すぐ下の支払元などの口座は `<select>` ドロップダウンのままで、同じ画面の中で選び方が揃っていない。口座も数個程度と一覧できる数なので、カテゴリと同じチップ型に揃えれば操作の一貫性が取れ、開く・選ぶの2タップが1タップになる。

## What Changes

- 取引入力フォームの口座選択（出費の「支払元」、収入の「入金先」、振替の「振替元」「振替先」、残高調整の「口座」）を `<select>` から、カテゴリと同じ横並びのチップ型ボタン群に変更する。
  - 支払元・入金先・振替元・残高調整の口座はフォーム上で同じ1つの要素で描画しているため、支払元だけでなくすべての口座選択をまとめてチップ化する（画面内の一貫性を優先した前提）。
- 各口座は1タップで選択・切り替えでき、選択中のチップはカテゴリと同じ見た目で強調する。
- 1行に収まらない場合は折り返して全口座を常時表示する。
- 選択できる口座の絞り込み（種類ごとの可否、非表示口座の除外、編集中の取引が使う口座は残す）と、振替元・振替先が同じ場合のエラーは現状どおり。
- 新規入力・編集のどちらの画面にも適用する（同じフォームを共有しているため）。

### Modified Capabilities
- `transactions`: 取引入力における口座（支払元・入金先・振替元・振替先・残高調整の口座）の選択を、カテゴリと同様に1タップのチップ型で行えることを要件として追加する。

- `src/index.css`: 既存の `.chips` スタイルを流用するため、原則変更なし。
- テスト: `src/pages/transactions.test.tsx`、`src/pages/settings.test.tsx` の `selectOptions` / `optionNames` による口座選択・検証をチップ方式に書き換え。
- データモデル・保存ロジック（`db/repository`、`domain/*`）への変更はなし。
