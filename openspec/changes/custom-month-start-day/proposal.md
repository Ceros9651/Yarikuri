# Proposal

## Why

いまの「1か月」は暦月（1日〜末日）に固定されている。クレジットカードの引き落とし日（例: 毎月5日）を区切りに家計を見たいユーザーにとっては、6日〜翌月5日を1か月とした方が、引き落とし額とその月の出費が対応して使いやすい（PBI-39）。

## What Changes

- 設定画面に「月の開始日」の設定を追加する。1〜28日から選べ、既定は1日（今までどおりの暦月）。
- 「月」の範囲を、開始日から翌月の開始日の前日までとする。期間は開始日のある月の名前で呼ぶ（開始日6日なら、2026年10月 = 10月6日〜11月5日）。
- 開始日を1日以外にしているときは、月の切り替えに月名と並べて期間（10月6日〜11月5日）を表示する。
- 月の範囲の変更は、次のすべてに効かせる。
  - ホーム: 月の収入・出費・差額、カテゴリ別の出費、カード別の利用額、口座別残高（期間の最終日時点）、予算の消化状況
  - 出費タブ（スマホ版）と取引一覧、取引一覧の見出しの合計、日付での絞り込み
  - PC 版の取引一覧のカレンダー（開始日から翌月の開始日の前日までを日曜始まりの週に並べる）
  - 出費保存時の予算アラート（取引の日付が属する期間で判定）
  - 起動時に表示する「今月」（今日が属する期間）
- 予算の設定記録の「月」は、開始日を変えても同じ名前の期間のまま扱う（記録の移し替えはしない）。
- 月の開始日を端末間で同期し、バックアップのファイルにも含める。バックアップの形式を version 3 にする。version 1・2 のファイルを読み込んだときは開始日を1日にする。

## Capabilities

### New Capabilities

（なし）

### Modified Capabilities

- `monthly-summary`: 月の範囲を開始日基準にし、月の開始日の設定・期間の表示を加える。口座別残高を期間の最終日時点にする。
- `transactions`: 取引一覧・PC 版のカレンダー・日付での絞り込みの範囲を、選択中の月の期間にする。
- `budgets`: 予算の月と出費保存時のアラートを、開始日基準の期間で判定する。
- `data-sync`: 月の開始日を同期の対象に加える。
- `data-backup`: エクスポート・インポートに月の開始日を含める（version 3）。

## Impact

- ドメイン: `src/domain/date.ts`（期間の算出）、`calendar.ts`、`summary.ts`、`budget.ts`、`balance.ts`、`backup.ts`、`types.ts`
- DB: `src/db/db.ts`（設定の表を追加する version 5）、`queries.ts`（期間の取引の読み込み）、`repository.ts`、`backup.ts`
- 同期: `src/sync/docs.ts`・`remote.ts`（設定のコレクション）、`firestore.rules`（コレクションの許可）
- 画面: `MonthContext`・`MonthSwitcher`、`HomePage`、`TransactionsPage`、`CategoryExpenses`、`SettingsPage` と新しい設定のセクション、`hooks/useData.ts`
- 口座×月の増減の表（balanceDeltas）は暦月のまま変えない。
