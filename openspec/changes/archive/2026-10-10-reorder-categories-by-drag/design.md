# Design

## Context

- `Category` は既に `sortOrder: number` を持ち、DB は `categories: 'id, kind, sortOrder'` でインデックス済み。`useCategories` / `useAppData` は `orderBy('sortOrder')` で取得しており、入力画面のチップ（`TransactionForm`）と予算設定（`BudgetsSection`）はこの順をそのまま使う。したがって `sortOrder` を書き換えるだけで全表示に反映される。
- `sortOrder` は種別をまたいだ通し番号（シードは種別ごとに 0 から、`addCategory` は全体の最大値 + 1）。値は相対順序にしか使われていない。
- バックアップ（`domain/backup.ts`）は `sortOrder` を含めて入出力済み。
- 主な利用環境はスマートフォンの PWA。HTML5 の Drag and Drop API はモバイルのタッチで動かない。

## Goals / Non-Goals

**Goals:**
- 設定画面の表示中カテゴリ一覧をタッチ・マウスでドラッグ並べ替えできる。
- 並べ替えロジックを UI から切り離し、単体テストで検証できる形にする。

**Non-Goals:**
- 入力画面のチップ上での直接並べ替え（タップ選択と競合するため）。
- 口座の並べ替え（同じ仕組みで後から対応可能だが今回は対象外）。
- 使用頻度による自動並べ替え。

## Decisions

### 1. ドラッグ実装に `@dnd-kit`（core / sortable / utilities）を使う
- タッチ・マウス・キーボードのセンサー、縦リストのソート、ドラッグ中の自動スクロールが揃っており、React 19 で動作する。
- 代替案: HTML5 DnD API（タッチ非対応のため不可）、Pointer Events で自作（スクロール抑止・自動スクロール・アクセシビリティを自前で作る必要があり割に合わない）。

### 2. ドラッグはハンドル（⋮⋮）からのみ開始する
- 行全体をドラッグ対象にすると、一覧の縦スクロールや「名前変更」「非表示」ボタンのタップと競合する。ハンドルに `touch-action: none` を付け、`PointerSensor`（`activationConstraint: { distance: 4 }` 程度）と `KeyboardSensor` を使う。
- ハンドルには `aria-label="<名前>を並べ替え"` を付ける。

### 3. 保存は `reorderCategories(orderedIds)` で、既存の `sortOrder` 値を並べ直して再割り当てする
- 引数は表示中カテゴリの新しい順序の ID 配列。対象カテゴリの現在の `sortOrder` 値を昇順に並べた集合を取り、新しい順序の先頭から順に割り当てる（1トランザクションで `bulkUpdate` 相当）。
- こうすると非表示カテゴリや他種別のカテゴリの `sortOrder` は変わらず、使われる値の集合も変わらないため、非表示カテゴリを再表示したとき元の相対位置に戻る（spec の再表示シナリオ）。
- 渡された ID がすべて同一種別で存在することを検証し、違反時はエラーとする（種別またぎの防止）。
- 並べ替え計算そのもの（配列の要素移動）は `@dnd-kit/sortable` の `arrayMove` を使う。
- 代替案: 0..n-1 で振り直す（非表示・他種別の位置関係が崩れる）、小数の中間値を割り当てる（精度劣化・重複処理が必要で過剰）。

### 4. ドロップ時はまず楽観的に表示を更新する
- `useLiveQuery` の反映を待つとドロップ直後に元の位置へ一瞬戻るちらつきが出るため、コンポーネント内でドラッグ後の順序をローカル state に持ち、保存完了後に DB の値へ戻す（DB 値が変われば state を破棄）。

## Risks / Trade-offs

- [依存追加でバンドルが増える] → `@dnd-kit` は core+sortable で gzip 十数KB程度。許容範囲。
- [jsdom ではドラッグ操作の結合テストが難しい（座標が 0 になる）] → 並べ替えの保存ロジックは `repository` の単体テストで網羅し、UI はハンドルの存在と `reorderCategories` 呼び出し後の表示順をテストする。実際のドラッグはブラウザ（スマホ幅のエミュレーション含む）で目視確認する。
- [ドラッグ中に名前変更フォームを開いている行がある] → 編集中の行はハンドルを無効化する。

## Migration Plan

- DB スキーマ・データ形式の変更なし。既存の `sortOrder` をそのまま使うため移行不要。ロールバックはコードを戻すだけでよい。
