# Design

## Context

- `NewTransactionPage` は `TransactionForm` の `onSaved` で `navigate('/', { state: { budgetAlert } })` を呼び、ホームへ移動している。
- 予算アラートは `Layout` の `BudgetAlertNotice` が `location.state.budgetAlert` を読んで表示する。画面を移動すると `state` が変わるので消える。
- `TransactionForm` は新規・編集の両方で使われる。`initial` があれば編集モード（種類ボタンを無効化）。カテゴリ・口座は `categoryId` / `accountId` が空なら `pick()` で選択肢の先頭を選ぶ。
- `EditTransactionPage` は保存後に `/transactions` へ移動する。これは変えない。

## Goals / Non-Goals

**Goals:**
- 新規入力の保存後に入力画面にとどまり、金額・メモ・カテゴリだけを初期状態に戻す。
- 保存完了メッセージを入力画面の上部に出す。
- 予算アラートは既存の `BudgetAlertNotice` の仕組みのまま入力画面に出す。

**Non-Goals:**
- 編集画面の保存後の動きの変更。
- 自動で消えるトースト、保存の取り消し（Undo）機能。
- 「続けて入力」と「保存してホームへ」の切り替えボタン。

## Decisions

### 1. フォームのリセットは `TransactionForm` 内で行う

新規モード（`initial` なし）の保存成功時に、フォーム自身が `setAmount('')`・`setMemo('')`・`setCategoryId('')`・`setErrors({})` を行う。`type`・`date`・`accountId`・`toAccountId` は触らない。`categoryId` を空にすると既存の `pick()` により選択肢の先頭（画面を開いたときと同じ初期選択）に戻る。編集モードではリセットしない（保存後に画面ごと移動するため）。

- 代替案: `NewTransactionPage` が `key` を変えてフォームを再マウントし、引き継ぐ値を初期値の props で渡す。→ 引き継ぎ用の props（`defaults` など）を追加する必要があり、編集用の `initial` との区別も増える。状態を持っているフォーム内でリセットするほうが変更が小さい。
- リセット後は金額欄にフォーカスを移し、次のレシートをすぐ打てるようにする（金額欄の `ref` を使う）。

### 2. 保存内容の要約をフォームから渡す

完了メッセージに種類・カテゴリ名（振替は「振替元→振替先」、残高調整は口座名）・金額を出すため、`onSaved` に第 3 引数 `summary: string` を追加し、フォームが保存直前の選択値と名前から組み立てて渡す（例: `出費・食費 ¥800`）。金額表示は既存の `formatYen` を使う。残高調整は保存される調整額ではなく、ユーザーが入力した「実際の残高」を表示する（例: `残高調整・財布 ¥5,000`）。

- 代替案: ページ側で保存した `id` から取引を引き直して組み立てる。→ 非同期の再取得とカテゴリ・口座名の解決をページに重複して書くことになる。フォームは名前を既に持っている。
- `EditTransactionPage` は第 3 引数を無視するだけで変更不要。

### 3. 完了メッセージはページのローカル状態、予算アラートは `location.state`

- `NewTransactionPage` が `savedMessage` を `useState` で持ち、`<h1>` の直下に `role="status"` のメッセージとして表示する。ページから離れるとアンマウントで消え、戻ってきても表示されない。
- 保存成功時は `navigate('/new', { replace: true, state: { budgetAlert } })` で同じ画面にとどまりつつ `state` を更新する。同じルートなのでページは再マウントされず、フォームの引き継ぎ値も保たれる。`budgetAlert` が `null` の保存では `state` も更新されるので、前回の予算アラートが残り続けることはない。`replace` にすることで、連続保存しても戻る操作の履歴が増えない。
- 保存失敗時に完了メッセージを消すため、フォームに `onError?: () => void`（または保存開始時に呼ぶコールバック）を追加し、ページは `savedMessage` を `null` にする。
  - 代替案: 保存開始時に常にメッセージを消す。→ 成功時に一瞬消えて再表示されちらつくため、失敗時だけ消す。

## Risks / Trade-offs

- [保存後に画面が変わらず、保存されたか分かりにくい] → 完了メッセージに内容（カテゴリ・金額）を含め、どの取引が保存されたか確認できるようにする。
- [日付・口座を引き継ぐため、別の日のレシートを前の日付のまま保存してしまう] → 日付欄は金額欄のすぐ上にあり目に入る。ユーザーの選択（引き継ぐ項目）として受け入れる。
- [予算アラートと完了メッセージが同時に出て画面上部が混む] → 予算アラートは `Layout` 側、完了メッセージは見出しの下と位置が分かれており、どちらも 1 行で収まる。
- [既存テストがホームへの移動を前提にしている] → `transactions.test.tsx` の該当テストを入力画面にとどまる前提に書き換える（tasks.md 参照）。
