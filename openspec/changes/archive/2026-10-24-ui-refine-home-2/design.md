# Design

## Context

- 前提は `desktop-layout` の PC 版（`src/index.css` 末尾の `@media (min-width: 1024px)` ブロック）。そこでは `.month-switcher` に `max-width: 480px` を付けるだけで、並びはスマホ版の `justify-content: space-between`（前月ボタン｜月名｜次月ボタン）のままになっている。
- `MonthSwitcher` はホーム、取引一覧（`TransactionsPage.tsx`）、設定の予算（`BudgetsSection.tsx`）の 3 か所で使う共通の部品。
- `.tab-bar` の背景はスマホ版の下部タブバー用の `background: var(--surface)` で、PC 版でもそのまま使われている。

## Goals / Non-Goals

**Goals:**

- PC 版のブロックの中だけで直し、スマホ版の見た目と `:root` のトークンは変えない。
- DOM の順（読み上げの順）を変えない。

**Non-Goals:**

- 月の切り替えに「今月へ戻る」ボタンを足すなど、操作を増やすこと。
- カテゴリ別の出費の行のホバー表示（次回のレビューで扱う）。

## Decisions

### 1. 月の切り替えの見た目の順は CSS の `order` で変える

- PC 版で `.month-switcher { justify-content: flex-start; gap: 8px }`、`.month-switcher h2 { order: -1; margin-right: auto }` とする。月名が先頭（左端）に来て、残りの 2 つのボタンが右端にまとまる。
- `MonthSwitcher.tsx` の DOM を並べ替える案は、スマホ版の並び（ボタン｜月名｜ボタン）まで変わり、読み上げの順も「月名 → 前月 → 次月」に変わるので採らない。
- `order` は見た目だけを変えるので、Tab キーで移る順は「前月 → 次月」のまま（月名はフォーカスされない）。視覚の順（月名 → ‹ → ›）とずれるのはボタン 2 つの間だけで、順番は保たれる。

### 2. ホームだけ月の切り替えを左列の幅にそろえる

- `.content:has(.home-columns) .month-switcher { max-width: calc((100% - 48px) / 2) }` とする。48px は `.home-columns` の `column-gap` と同じ値で、左列の幅（本文が最大幅 1040px のとき 456px、1024px 画面のとき約 340px）と一致する。
- 列の間隔をトークンにする案（`--home-column-gap`）は、使う場所が 2 か所だけなので今回は採らない。値を変えるときに両方を直すよう、CSS にコメントを付ける。
- ホーム以外（取引一覧・設定の予算）は、PC 版の `max-width: 480px` を外して親（本文・カードの内側）の幅いっぱいにし、‹ › の右端を下の一覧・カードの中身の右端とそろえる（`/ui-review --verify` で、480px のままだと右端がどこにもそろわないと分かったため）。
- カードの中の月の切り替え（設定の予算）は、左寄せにすると月名（1.1rem）がカードの見出し（1rem）より大きく見えるので、PC 版では `.card .month-switcher h2` を 1rem にする。

### 3. サイドバーは背景を `--bg` にし、上の余白を本文に合わせる

- PC 版の `.tab-bar` に `background: var(--bg)` を指定し、`border-right` の 1px 線だけで区切る。`padding-top` を `.content` と同じ 32px にし、`.nav-title` を `line-height: 44px`（月の切り替えのボタンの高さ）にして、アプリ名と月名の中心をそろえる。
- 一段沈んだ色（`--surface-2`）で塗る案は、ダークモードでは `--surface-2` が `--bg` より明るく、逆に浮いてしまう。ダーク用に別のトークンを足す必要があるので採らない。
- 取引一覧・入力・設定は 1 行目が `h1` なので、PC 版では `h1` も `line-height: 44px` にして、アプリ名と見出しの中心をそろえる。見出しの下の間隔は `margin-bottom: 4px` で今とほぼ同じにする（当初はずれを許容する予定だったが、`/ui-review --verify` で 7px のずれが spec と食い違うと分かったため直す）。ホームの `h1` は読み上げ用で画面に出ないので影響しない。

### 影響する画面ごとの見た目の変化（PC 版だけ）

| 画面 | 月の切り替え | サイドバー |
| --- | --- | --- |
| ホーム | 月名が左端（差額とそろう）、‹ › が左列の右端 | 背景が本文と同じ灰色、罫線 1 本 |
| 取引一覧 | 月名が左端、‹ › が一覧カードの右端。見出しの行の高さが 44px | 同上 |
| 設定（予算） | 予算セクション内の月の切り替えが同じ並びで、‹ › はカードの内側の右端、月名は 1rem。見出しの行の高さが 44px | 同上 |
| 入力・取引の編集 | 月の切り替えなし | 同上 |

## Risks / Trade-offs

- [`:has()` 非対応のブラウザでは、ホームの月の切り替えが 480px のままになり、1024px 付近で右列の上に少しかかる] → `desktop-layout` と同じく、PC は最近のブラウザを想定して許容する。
- [サイドバーの背景が本文と同じになり、境界が弱く見える] → 1px の罫線は残すので境界は分かる。`/ui-review --verify` で確認する。
