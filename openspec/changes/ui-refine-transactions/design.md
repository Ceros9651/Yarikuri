# Design

## Context

- 取引一覧は transactions-calendar-desktop（未アーカイブ）で、PC 版に左のカレンダー（3:2 の左列）と日付の絞り込み（URL の `date`）が入った状態。この change はその上に積む。
- 絞り込みは `FilterChips`（`.field` > `.chips` の `button[aria-pressed]`）で、入力画面の `TransactionForm` も同じ `.chips` / `.field` を使っている。
- 一覧は `section.card[aria-label="取引"]`。`.card` は設定画面の 5 セクションでも使っている。
- ホームは見出しと合計を `.section-head`（下に 1px の罫線、`.amount` は太字）で並べている。

## Goals / Non-Goals

**Goals:**

- 指摘 4 件（金額の揃え方、絞り込みの占める高さ、合計がない、一覧のカード）をこの画面の中だけで直す。

**Non-Goals:**

- 共通の `.card` / `.chips` / `.field` / `.section-head` の定義の変更（他画面に波及するため）。
- スクロールバーの有無による列の幅のずれ、1920px で行の項目名と金額が離れること、選択中の日の印の太さ（次回のレビューに回した）。

## Decisions

### 1. 絞り込みの操作は native の `<select>` をボタンの見た目に装う

- 条件ごとに `label`（「カテゴリ」「支払元」）付きの `<select>` を置き、`.tx-filters` の下だけで枠・角丸 999px・余白をチップと同じにして、右端に ▾ を付ける。選択中の値は `<select>` がそのまま表示する。
- 理由: 開閉・キーボード操作・読み上げ（combobox と選択中の値）をブラウザに任せられ、スマホでは OS の選択画面が開いて片手で選びやすい。URL の `category` / `account` との対応も、`value` と `onChange` だけで今の `setFilter` に載る。
- 代案: 独自のポップオーバー（ボタン＋メニュー）は、フォーカスの管理・外側クリックで閉じる・読み上げを自前で作る必要があり、この画面の規模に見合わないので採らない。チップの横スクロール 1 行は、選択肢が隠れて「すべて見える」利点がなくなるうえ、spec の書き換えも必要になる点は同じなので採らない。

### 2. 見出しの行は `.section-head` を再利用し、日付の絞り込みの行を統合する

- `<div className="section-head">` に `h2`（「10月の取引」/「10月14日の取引」）、日付の絞り込み中は解除の `button.link`、右端に `span.amount`（出費の合計）を置く。合計は表示中の `rows` から出費だけを足す。
- `.tx-day-filter` の行は見出しの行に統合して消す。スマホでも見出しの行は出るので、日付の絞り込みの解除は引き続きどの幅でもできる。

### 3. 一覧はカードのクラスを外すだけにする

- `section[aria-label="取引"]` は残し（テストと読み上げが使う）、`card` クラスだけ外す。区切りは `.section-head` の下罫線と `.list` の行の罫線になる。
- PC では `.tx-row:hover` の背景を `--surface-2` にして、行が押せることを示す。

## Risks / Trade-offs

- [選ぶのに 2 回の操作（開く→選ぶ）が要る] → 既存の要件を書き換えてユーザーが選んだ。選択中の値は常に操作の文字で見えるので、絞り込み中であることは分かる。
- [既存の絞り込みのテストが `aria-pressed` 前提で大量に壊れる] → tasks 2.1 で `combobox` の選択に書き換える。テストの意図（どの取引が出るか）は変えない。
- [native の `<select>` の見た目はブラウザ・OS で差が出る] → `appearance: none` で枠と ▾ を自前にし、開いたときの一覧だけ OS に任せる。

## Migration Plan

- データの移行はない。戻すときはこの change のコミットを revert する。
